# 最小 Harness 实现规则

## 1. 目标与边界
实现最小可运行闭环：接收输入 → 构建上下文 → 请求模型 → 执行工具 → 回传结果 → 继续循环或结束。
本项目不实现审批策略、权限限制、工具沙箱及 MCP。

## 2. 分级命令
### 一级：`/harness-self <任务>`
自主设计实现。先分析本地项目，明确流程、接口和改动范围，再编码；不要求参考 Codex 源码。

### 二级：`/harness-codex <任务>`
先分析 Codex 源码，再转换为本项目实现。完成第 3 节前，禁止生成实现代码。

未指定命令时默认 `/harness-codex`；仅显式 `/harness-self` 可跳过上游源码分析。

## 3. 源码分析
- 仅使用 GitHub `openai/codex` 官方仓库源码，优先读取本地克隆。
- 固定 commit：`2351d9e1b608e6f9d9a3699b71d7eb39ee41cfa4`，不得以其他版本替代。
- 本地仓库路径未提供时先确认；缺失时可读取 GitHub 同一 commit。
- 禁止以网上文章、搜索摘要或记忆替代源码证据。
- 优先追踪核心入口与主要方法调用链，标注文件、符号及固定版本链接。
- 说明输入输出、循环状态、工具结果回传与终止条件；剥离第 1 节排除项。

## 4. 转换与验证
先给出调用链及“上游职责 → 本项目模块”映射，再编码。
仅保留闭环必需能力，适配本地接口，不照搬上游架构。
验证普通回复、工具调用、异常与终止；未验证项明确标注。
